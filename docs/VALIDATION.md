## 개발 도구

- Flutter 3.50.1 / Dart 3.14.0.
- Temurin JDK 21.0.13.1, Android SDK 36, build-tools 36.0.0, NDK 28.2.13676358.
- `flutter_local_notifications` 22.3.3. SDK 37을 요구하는 23.0.4 대신 현재 빌드 가능한 버전으로 선택했다.
- 전체 의존성 버전은 `pubspec.lock`에 기록한다.

## Android 테스트 파일

- 경로: `build/app/outputs/flutter-apk/app-release.apk`.
- 크기: **18,120,195 bytes** (빌드 표시 18.1MB).
- SHA-256: `150879c1a1a80e84775db18a0189dcfeeeea3f398e106a1097ad71e9c245177b`.
- 패키지: `app.hydration.hydration_app`, 버전 `0.1.0+1`.
- ABI: `arm64-v8a` 전용. 최소 Android API 24, 대상·컴파일 API 36. 이 수치는 매니페스트 설정이며 해당 OS 전체에서 실행을 확인했다는 뜻이 아니다.
- release 구성도 Flutter 템플릿의 개발용 debug 키로 서명했다. 스토어 제출용 서명·배포 결과는 아니다.
- APK와 SDK·서명 파일은 Git에 넣지 않는다. 원본 코드와 의존성 잠금 파일로 다시 빌드한다.

초기 빌드는 시스템 JRE의 컴파일러 부재, SDK 버전 요구, 약 8GB 작업 공간의 용량 부족으로 실패했다. JDK 설치·의존성 조정·재생성 가능한 설치 자료 정리 후 위 명령이 성공했다. 실패했던 명령을 통과한 것으로 처리하지 않았다.

## 실행 방법과 다음 실기기 확인

개발 환경에서는 저장소 루트에서 실행한다. Android SDK·전체 JDK와 실행 대상 기기가 필요하다.

```sh
flutter pub get
flutter run
```

생성 APK로 확인한다면 arm64 Android 기기를 연결한 후 다음 명령을 사용할 수 있다. ADB 연결과 설치는 이 작업에서 수행하지 않았다.

```sh
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

1. 하루 목표를 직접 입력하고 200mL·100mL 기록으로 합계와 진행률을 확인한다.
2. 앱을 닫고 다시 열어 목표·기록·선택 언어가 남는지 확인한다. 날짜별 조회와 삭제 결과도 확인한다.
3. 설정에서 영어·중국어 간체/번체·일본어·한국어·힌디어를 선택해 문구와 숫자를 확인한다.
4. ‘1분 뒤 알려주세요’를 누르고 알림 권한을 허용한다. 전체·절반 액션 각각으로 해당 표시량이 한 번만 기록되는지 확인한다. 목표까지 남은 양이 200mL보다 적은 경우도 확인한다.
5. 권한 거부, 앱을 닫은 상태, 기기 재부팅, 절전 모드, 날짜·시간대 변경을 별도 사례로 기록한다. Android는 정확한 알람 특수 권한을 사용하지 않으므로 OS가 발송을 지연할 수 있다.
