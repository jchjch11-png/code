# Sol 현지화 업무지침서

현지화 담당은 Sol이다. 제품 요구사항 P05·P11·P12와 화면·알림·보상·접근성의 공통 현지화 규칙을 구체화한다.
현재 S0에서는 업무지침을 작성한다. 전체 번역, 코드 변경, 패키지 설치, 스토어 제출은 후속 단계에서 진행한다.
제품과 작업 권한은 [제품 요구사항](../PRODUCT.md) 및 [저장소 업무 규칙](../../AGENTS.md)을 따른다.

## 지원 언어와 유통 지역

| 언어 | 런타임 BCP 47 태그 | Flutter ARB 파일명 초안 |
|---|---|---|
| 영어 | `en` | `app_en.arb` |
| 중국어 간체 | `zh-Hans` | `app_zh_Hans.arb` |
| 중국어 번체 | `zh-Hant` | `app_zh_Hant.arb` |
| 일본어 | `ja` | `app_ja.arb` |
| 한국어 | `ko` | `app_ko.arb` |
| 힌디어 | `hi` | `app_hi.arb` |

- 초기 6개 로캘을 선택 가능한 언어팩으로 앱에 번들한다. 다운로드 없이 첫 실행부터 선택할 수 있다.
- 인도는 여러 언어가 쓰이는 국가다. 초기에는 힌디어와 영어를 제공한다는 가정을 적용하고 벵골어(`bn`), 타밀어(`ta`), 텔루구어(`te`)를 확장 후보로 둔다.
- 중국어 언어팩 제공과 중국 본토 출시는 별개다. 중국 본토 출시 국가 지정, Android 유통 채널, 현지 스토어 자료와 출시 요건은 출시 담당이 따로 검토한다.
- 초기 앱 유통 계획은 App Store·Google Play를 기준으로 한다. 앱 지원 언어, 스토어 페이지 제공 언어, 판매 국가 목록을 각각 관리한다.

## 런타임 언어와 저장 계약

- Flutter의 ARB와 `gen-l10n`을 초기안으로 사용한다. 영어 ARB를 원문 템플릿으로 두고 지역화 지원 목록을 생성 결과와 일치시킨다.
- ARB 파일명에는 밑줄을 사용한다. 설정 저장, 지원 목록 비교, 네이티브 알림 연동에서는 정규화한 BCP 47 태그를 사용한다.
- 첫 실행은 시스템 자동을 기본안으로 둔다. 온보딩 첫 화면과 설정에서 언어 선택에 접근할 수 있게 하고, 언어 이름은 해당 언어로 표시한다.
- 저장 계약에는 ‘시스템 자동’ 또는 직접 선택한 태그를 기록한다. 앱 재시작 후 저장값을 복원하고 직접 선택 시 화면과 접근성 문구에 즉시 반영한다.
- 시스템 자동에서는 OS 선호 언어 순서대로 지원 로캘을 찾는다. 언어·문자체·지역이 포함된 태그를 정규화하고 지원되는 언어팩으로 해석한다.
- 중국어는 명시적 `Hans`·`Hant`를 우선한다. 문자체가 없을 때 `CN`·`SG`는 간체, `TW`·`HK`·`MO`는 번체로 매핑하고, 지역 정보도 없는 `zh`는 간체를 초기안으로 둔다.
- 지원 언어를 찾을 수 없거나 저장된 태그가 유효하지 않으면 영어로 표시한다. 릴리스 검사에서는 누락 키를 실패 처리하고 런타임 복구는 영어를 사용한다.
- 지원 언어 목록과 매핑 표는 공통 계약으로 관리한다. Flutter와 네이티브 알림에서 동일한 사례로 일치 여부를 검증한다.
- 시스템 자동 상태에서 OS 선호 언어가 바뀌면 앱 활성화 시 유효 언어를 다시 계산한다. 네이티브에서 변경을 감지할 수 있는 시점은 시제품에서 확인한다.

## 지역 형식과 데이터 경계

- 표시 언어, 국가·지역, 표시 단위, 시간대는 서로 독립된 설정으로 다룬다. 최초 기본값은 기기 설정을 우선한다는 가정을 적용한다.
- 숫자, 소수점·자릿수 구분, 날짜 순서·월 이름, 12/24시간 형식, 주 시작일은 지역 규칙과 기기 설정에 맞춘다. 요일 라벨과 달력 열 배치를 함께 확인한다.
- 시계 형식과 주 시작일을 가져오는 OS API 및 적용 우선순위를 S1 계약서에 기록한다. 기기 값이 없을 때의 지역별 기본값도 정한다.
- 지원 표시 단위는 mL/L, US fl oz, kg/lb다. 단위 기호와 여백, 숫자를 포맷하고 직접 입력에는 지역별 소수점 문자를 허용하는 방안을 검증한다.
- 현지화 화면에서 반올림한 값은 표시에만 사용한다. 사용자 입력은 도메인 계약에 따라 기준 단위로 변환하고 필요한 반올림을 한 번 적용한다. 정밀도와 재편집·단위 전환 왕복 오차 기준은 도메인 담당과 합의한다.
- 섭취 기록과 목표 계산에는 도메인의 기준 단위와 정밀도를 사용한다. 표시 포맷 변경에도 저장량, 달성률, 보상 구간이 동일한지 확인한다.
- 알림의 예약 시각과 하루 경계는 시간대 계약을 따른다. 언어·지역 변경으로 날짜 키나 저장 기록이 이동하지 않는지 검증한다.

## 문자열, 화면과 접근성

- 온보딩, 목표 안내, 알림 권한 안내, 기록·달력, 오류·확인 메시지, 스티커 이름·설명과 접근성 라벨을 키 목록에 넣는다.
- 화면과 OS에 노출되는 전체 문장을 번역한다. 문자열을 이어 붙이는 대신 자리표시자, ICU 복수 규칙, 현지화된 숫자·날짜 포맷을 사용한다.
- 영어 ARB에 키의 의미, 문맥, 변수 타입·예시, 짧은 버튼 여부를 기록한다. 원문의 자리표시자 이름·타입과 번역의 복수 분기를 검사한다.
- 물 섭취 목표와 보상 문구는 제품 기준에 맞춰 검토한다. 권장 목표의 의미와 수정 가능성을 정확히 전달하고 과도한 섭취 유도를 피한다.
- 간체·번체 글리프와 일본어·한국어 글꼴 대체를 실제 화면에서 점검한다. 힌디어는 데바나가리 글꼴, 모음 기호, 결합문자와 줄바꿈을 확인한다.
- 글꼴을 번들해야 할 경우 라이선스, 용량, 플랫폼별 렌더링을 확인한다. 공백 분할이나 고정 문자 수 자르기로 결합문자가 깨지지 않게 한다.
- 큰 글자, 좁은 폰 화면, 태블릿 분할 화면에서 잘림·겹침·의미 손실을 확인한다. 스티커와 진행률에는 스크린리더로 읽을 수 있는 정보를 제공한다.
- 초기 6개 로캘의 표시 방향은 LTR이다. 향후 RTL 지원을 위해 방향 기준 여백과 정렬을 사용하고 숫자·단위·혼합 방향 텍스트 검증 항목을 남긴다.
- AI는 번역 초안과 용어 정리에 활용할 수 있다. 출시 대상으로 표시할 번역은 언어별 원어민 검수자가 문맥과 실제 화면을 검토하고 결과를 기록한다.

## 네이티브 알림

- 본문과 동작 제목에 같은 유효 로캘을 사용한다. 100%·50% 기록의 의미와 예정량에서 계산한 실제 mL를 P05에 맞게 전달한다.
- 현지화 담당은 키·치환 변수·표시용 단위 형식과 짧은 버튼 문구를 제공한다. 알림 담당은 OS별 동작 제목 등록, 예약 변경, 백그라운드 적용을 맡는다.
- 유효 언어가 바뀌면 새 예약에서 새 문구를 사용한다. 기존 미발송 알림은 예약 의도와 식별자를 보존해 교체하는 방안을 시제품에서 검증한다.
- 이미 전달된 알림은 OS에서 교체할 수 있는지 확인하고 가능한 동작을 기록한다. 언어 변경 중 빠른 기록을 눌러도 기존 동작 식별자와 멱등 키가 연결되어야 한다.
- iOS 알림 카테고리의 동작 제목과 Android 알림 동작 제목을 각각 확인한다. 잠금 화면, 확장 UI, 앱 미실행 상태, 재실행 후 예약에서 실제 노출을 확인한다.
- 자동 설정의 OS 언어 변경, 수동 팩 전환, 예약 교체 도중 종료·재시도, 알림 권한 거부에서 언어와 예약 누락·중복을 점검한다.

## 언어팩 추가와 출시 검수

1. 수요, 지원 언어·문자체 태그, 원어민 검수 가능 여부를 확인하고 메인과 지원 범위를 정한다.
2. 영어 템플릿의 키·메타데이터를 기준으로 ARB를 추가한다. 언어 이름, 우선순위, 시스템 매핑, 번들 목록을 갱신한다.
3. 키 일치, 자리표시자 타입, ICU 구문과 복수 분기, 줄바꿈·말줄임을 검사한다. 지원 범위에 맞게 글꼴·표시 방향도 확인한다.
4. 앱 화면과 실제 OS 알림, 스크린리더, 오프라인 설치, 자동·수동 언어 선택, 업데이트 후 저장값을 검증한다.
5. 출시 담당과 스토어별 메타데이터 태그·글자 제한을 확인하고 제목, 설명, 스크린샷, 변경사항을 앱에서 쓰는 용어에 맞춰 검수한다.
6. 검수자와 빌드 버전, 확인한 기기·OS, 남은 결함을 기록하고 지원 언어 목록과 출시 자료에 반영한다.

- 각 검증 기록에는 재현 순서, 예상·실제 결과와 결함 링크를 남긴다. 자동 점검 결과와 기기에서 확인한 결과는 각각 기록한다.
- 최종 번역 검수는 기능 의미, 지역 용어, 화면 배치, 보조 기술 발화, 스토어 자료의 일관성을 확인한다.
- 숫자·단위 해석 오류, 언어 설정 유실, 핵심 문구 누락, 알림에서 기록량이 오해되는 경우는 출시 검토에 전달한다.

## 소유권과 미정 항목

- Sol 현지화는 키·용어·문구·검수 기준과 현지화 결함을 맡는다. UX 담당은 언어 선택 동선, 화면 잘림과 접근성 구현을 맡는다.
- 도메인 담당은 저장 단위·정밀도, 기록 날짜와 시간대 해석을 맡는다. 아키텍처 담당은 앱 설정 연동을 맡고 메인이 공통 설정 변경과 계약을 통합한다.
- 알림 담당은 OS별 리소스와 예약 갱신을 맡고 품질·출시 담당은 기기 검증 기록과 스토어 제출물을 관리한다. 언어별 원어민이 번역과 표현을 확인한다.
- S1에서 지역 기본값의 우선순위, 주 시작일을 가져오는 방식, 단위 변환 정밀도와 반올림, ARB 생성 설정, 글꼴 자산 여부를 확정한다.
- S2에서 앱 미실행 중 시스템 언어 변경의 반영 시점과 OS별 예약 교체 범위를 확정한다.
- 원어민 검수자, 출시 국가와 스토어 등록 언어, 중국 본토 유통 범위, 추가 인도 언어의 우선순위는 미정이다.
