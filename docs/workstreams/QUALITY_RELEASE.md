# 품질 검증과 스토어 출시 업무지침

Astra 품질·출시 담당은 [제품 요구사항](../PRODUCT.md)의 P01~P12를 시험 사례, 기기별 결과, 출시 후보 빌드에 연결한다.
현재 S0의 산출물은 이 업무지침이다. 아래 단계의 시험·심사·공개는 후속 작업이다.

## 책임과 증거 관리

- 품질 담당은 후속 구현 시 배정받을 `qa/`의 인수 사례·기기 매트릭스·결함 목록, `release/`의 출시 판정표·스토어 자료 목록·운영 기록을 소유한다.
- 기능 담당은 모듈 시험과 결함 수정을 소유한다. 네이티브 담당은 OS별 로그를, 현지화 담당은 번역 리소스와 검수 결과를 전달한다.
- 메인은 공통 설정·서명 연동 변경을 통합하고 공개 권한 범위를 확인한다. 자격증명·서명 키는 증거 파일에서 제외한다.
- 사례마다 요구사항 ID, 사전 데이터, 재현 순서, 기대값, 실제값, 빌드 식별자, OS·기기, 실행일, 담당자, 증거 위치를 남긴다.
- 미실행·실패·통과 및 적용 제외 사유를 기록한다. 재시험에는 수정 빌드와 이전 실패를 연결한다.
- 자동 검사는 계산·저장·이전·리소스 계약 결과를 남긴다. 에뮬레이터·시뮬레이터는 API 경계와 화면 조합의 실행 증거를 남긴다.
- 실기기 증거는 기기 모델·OS 빌드·설정값과 관찰 영상 또는 로그다. 번역 검수에는 언어별 검수자와 수정 확인을 기록한다.
- 시험 트랙 설치, 심사 승인, 국가별 공개, 스토어판 설치·실행은 각각 트랙·버전·시각과 별도 증거를 남긴다.

## 단계별 인수 절차

### S0 문서

- 업무 — 제품 범위, 검증 책임, 단계 의존성을 대조한다.
- 산출물 — 업무지침과 요구사항에 대응하는 인수 기준.
- 수용 — 네 기기·여섯 언어팩·두 스토어의 증거 요건이 있고 미확정 조건을 후속 단계에 배정했다.

### S1 기반·계약

- 업무 — 목표 산정 근거·예외, 일자 귀속, 목표 이력, 알림 식별자·반올림, 보상 재계산, 저장 버전 계약을 담당자와 합의한다.
- 산출물 — P01~P12 사례 목록, 민감정보 없는 고정 시험 데이터와 기대값, OS 후보 매트릭스.
- 수용 — 동일 입력에 대한 기대 일자·mL·등급이 하나로 정해지고 이전 데이터와 오류 복구 사례가 있다.

### S2 알림 시제품

- 업무 — Apple과 Android 실기기에서 예약·표시·액션 전달·저장까지 한 건을 추적하고 아래 상태별로 반복한다.
- 산출물 — OS 빌드·플러그인 후보별 로그, 예약 한계·제약·복구표, 지원 최소 OS 및 대안 제안.
- 수용 — 지원 상태에서 100%·50% 액션의 단일 저장을 재현하고 OS가 제한하는 상태의 안내·재진입 복구가 정의됐다.

### S3 전체 기능·지역화

- 업무 — 프로필·직접 목표, 자동·수동 알림, 컵·직접량 수정, 진행 그림·수치, 보상과 달력을 연결해 시험한다.
- 산출물 — 도메인·저장소 자동 검사 결과, 화면·접근성 사례, 언어별 검수표.
- 수용 — 아래 경계값·기록 이전 검사가 통과하고 여섯 언어팩에서 첫 실행부터 달력까지 진행할 수 있다.

### S4 실기기 QA

- 업무 — 네 기기에서 새 설치와 지원 이전 버전 업그레이드를 구분해 핵심 경로를 실행한다.
- 산출물 — 기기별 결과, OS·권한·언어 조합, 결함 재현 및 수정 후 회귀 결과.
- 수용 — 네 종류의 실제 기기 증거가 있고 핵심 흐름에 출시 차단 결함이 0건이다.

### S5 시험 배포

- 업무 — 시험용 서명과 권한을 준비해 TestFlight와 Google Play 테스트 트랙으로 배포하고 테스터 계정에서 설치·업데이트한다.
- 산출물 — 트랙별 빌드 식별자, 초대·설치 결과, 피드백과 수정 확인, 계정별 정식 트랙 진입 조건.
- 수용 — 두 경로에서 설치·실행·알림 기록·재실행 후 보존을 확인하고 차단 피드백을 해소했다.

### S6 출시 빌드·자료

- 업무 — 최종 버전·빌드 번호, 앱 ID, 릴리스 서명·권한을 대조한다. 제출 빌드가 달라지면 변경 영향에 따라 재시험한다.
- 산출물 — 서명한 후보 식별자, 기기·언어별 실제 화면 캡처, 소개·지원 연락처·개인정보처리방침 URL과 심사 메모.
- 수용 — 서명·설치 증거, 앱 동작과 일치하는 스토어 개인정보 응답, 출시 국가 목록, 최종 번역 검수를 갖췄다.
- 제출 시점에 Apple [심사 지침](https://developer.apple.com/app-store/review/guidelines/)과 [제출 요건](https://developer.apple.com/news/upcoming-requirements/)을 확인한다.
- Google [개발자 정책](https://play.google/developer-content-policy/)과 Play Console의 해당 계정 안내에서 대상 API·테스트·자료 요건을 확인하고 확인일을 남긴다.

### S7 심사·공개

- 업무 — 승인된 계정·지역·일정 범위에서 제출하고 심사 상태를 추적한다. 단계적 배포가 가능하면 대상과 중단 기준을 기록한다.
- 심사 거절 시 지적 조항, 재현 환경, 자료·코드 수정 범위를 기록한다. 수정 후보를 재검증하고 답변과 함께 재제출한다.
- 산출물 — 제출·심사 기록, 스토어별 공개 버전·국가·링크, 일반 사용자 경로 설치·실행 결과.
- 수용 — 두 스토어에서 지정 국가에 공개되고 내려받은 버전의 첫 실행과 핵심 동작을 확인했다.
- 공개 권한은 실제 사용자 지시를 따른다. 기존 승인 범위는 그대로 적용하고 추가 확인이 필요하면 후보 빌드·자료·국가·판정표를 먼저 제시한다.

### S8 운영

- 업무 — 스토어 진단·사용자 문의에서 충돌, 기록 유실, 예약 누락과 번역 오류를 버전·OS별로 분류한다.
- 장애 시 추가 롤아웃을 중단하고 영향 범위와 복구 방식을 기록한다. 이미 설치한 기기는 중단 후에도 해당 버전을 사용한다.
- DB 스키마 전진 이전 후 구버전은 새 데이터를 읽지 못할 수 있다. 새 스키마를 보존하는 수정 버전과 보정 이전을 시험한다.
- 산출물 — 사건별 담당자·영향 버전·중단 시각, 수정 버전의 이전·회귀 결과와 재개 기록.
- 수용 — 복구판의 기존 데이터 보존·정상 동작을 확인하고 배포 재개 후 같은 결함의 재발 여부를 확인했다.

## OS와 실기기 매트릭스

| 실기기 종류 | OS 표본 계획 | 추가 관찰 |
|---|---|---|
| iPhone | 지원 하한 iOS와 최신 지원 iOS | 잠금 화면, 알림 펼치기, 집중 모드 |
| iPad | 지원 하한 iPadOS와 최신 지원 iPadOS | 가로·세로·분할 화면과 큰 글자 |
| Android 휴대폰 | 지원 하한과 최신 지원 Android, 권한 동작 전환 버전 | 잠금 화면 액션, 알림 채널, 절전 |
| Galaxy Tab | 지원 하한과 최신 지원 Android, 실제 One UI 버전 기록 | 대화면·멀티윈도우, 제조사 백그라운드 제한 |

- S2 이후 버전을 숫자로 확정해 모델과 OS를 짝짓는다. 기기가 부족한 OS 조합은 가상 환경 실행 여부와 남은 실기기 공백을 명시한다.
- 네 기기 모두 목표 설정 → 알림 빠른 기록 → 진행률·보상 → 달력 배치·재시작을 실행한다. 폰트 확대·화면 읽기에서도 핵심 동작을 확인한다.

## 알림 상태와 시간 경계

- 전경과 백그라운드(프로세스 생존)를 분리한다. 액션이 보이는 경로와 액션 후 앱을 열어야 하는지 기록한다.
- OS 메모리 회수 등 프로세스 부재는 별도 사례다. 예약 전달, 액션 콜백, 앱 재진입 후 저장 건수를 각각 관찰한다.
- iOS 앱 전환기 강제 종료, Android 최근 목록 제거, Android 설정의 강제 중지를 구분한다. 실제 조작과 재실행 전후 결과를 남긴다.
- 권한 최초 허용·거부·설정 철회·재허용, 채널 차단, 집중·절전 상태에서 호출 성공과 실제 노출을 따로 확인한다.
- 재부팅 후 첫 잠금 해제 전후, 오프라인과 재진입, 시간대 이동·수동 시각 변경·자정에서 기존 예약과 재구성 목록을 비교한다.
- DST 시작의 존재하지 않는 시각과 종료의 반복 시각에 대해 지역·날짜를 고정하고 계약에서 정한 건수와 현지 시각을 대조한다.
- 예약 가능 한계 전후를 채우고 예약 창 보충, 중복·누락, 취소·재예약을 확인한다. 알림 정밀도는 실제 OS 권한·정책별로 기록한다.
- 자동 알림은 나머지 용량과 조용한 시간을, 수동 알림은 추가·수정·삭제를 확인한다. 미루기·건너뛰기와 목표 달성 후 당일 예약 취소를 검증한다.
- 예정량 200mL의 두 액션은 각각 200mL·100mL로 표기·저장해야 한다. 홀수 예정량에는 S1 반올림 계약을 적용한다.
- 같은 예약 액션 재전달·연타·경합·저장 중 종료 후 재시도에서도 기록은 한 건이다. 서로 다른 정상 예약 두 건은 각각 보존한다.

## 데이터·보상 인수 사례

- 목표 1,000mL에서 499·500·501mL는 없음·50% 등급·50% 등급, 799·800·801mL는 50%·80%·80% 등급이다.
- 999·1,000·1,001mL는 80%·특별·특별 등급이다. 표시 반올림으로 등급이 조기 승급하지 않고 초과 보상이 생기지 않아야 한다.
- 추가·수정·삭제·복구로 경계를 양방향 통과할 때 당일 합계, 남은 양, 달력 스티커와 예약 상태를 계약의 기대값과 비교한다.
- 자정 전후, 여행 후 시간대 전환, 과거 기록 정정·목표 변경에서 영향을 받는 일자만 다시 계산하는지 확인한다.
- 달력 스티커를 붙이고 위치를 조절해 재시작한다. 등급 변경 시 배치·과거 확정 결과가 계약과 일치하는지 확인한다.
- 건강상 제한을 반영한 직접 목표와 권장량 설명을 검수한다. 현재량·목표량·남은 양·진행률을 색상 없이 읽을 수 있어야 한다.
- 지원하는 이전 DB 각 버전의 프로필·설정·섭취·배치 샘플을 이전하고 ID·건수·합계·날짜·위치·멱등 키를 대조한다.
- 이전 도중 중단과 재실행을 재현하여 부분 반영·중복·초기화 여부를 확인한다. 신규 설치의 빈 DB도 같은 스키마에 도달해야 한다.

## 언어팩 인수와 출시 판정

- en, zh-Hans, zh-Hant, ja, ko, hi 각각 시스템 설정 추종·수동 선택·오프라인 재시작·지원하지 않는 언어의 대체 경로를 시험한다.
- 간체·번체를 분리해 문자를 검수하고 일본어·한국어 줄바꿈, 힌디어 결합 문자와 큰 글자에서 잘림·겹침을 확인한다.
- 언어와 지역·시간대를 독립 변경해 날짜·요일·숫자·단위·12/24시간, 달력과 알림의 실제 mL 표기를 대조한다.
- 예약 후 언어를 바꿔 갱신 대상의 제목·액션·중복 여부를 확인한다. 스티커 설명·화면 읽기 레이블·목표 설명·스토어 소개도 번역 검수한다.
- 출시 국가는 언어팩과 별도로 확정한다. 중국 본토 Android는 별도 유통 채널·현지 요건 검토가 필요한 후속 범위다.
- 출시 차단 0건은 유실·중복, 핵심 경로 불능, 중대한 건강 안내 오류, 개인정보·서명·필수 제출 요건 불일치가 모두 해소됐다는 판정이다.
- 필수 증거 누락은 통과 보류로 기록한다. 경미한 잔여 결함은 영향·대응·담당자를 붙여 메인이 출시 후보별로 판단한다.
- Apple 서명·배포에는 macOS·호환 Xcode와 Apple Developer 권한, Play 시험·출시에는 Play Console 계정·트랙 권한이 필요하다.
- 실제 기기와 배포 네트워크는 해당 시험·제출 단계에서 확보한다. S0 문서 검수는 파일·링크·요구사항 대조로 완료할 수 있다.
