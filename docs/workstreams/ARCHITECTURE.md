# 아키텍처 리드 업무지침

## 책임과 상태

Astra 아키텍처 리드는 Flutter 앱의 계층 경계, 공통 데이터 계약, 플랫폼 간 차이와 통합 순서를 관리한다.
제품 기준은 [제품 요구사항](../PRODUCT.md), 공통 권한은 [팀 업무 규칙](../../AGENTS.md)을 따른다.

| 구분 | S0 기준 |
|---|---|
| 결정 | 현재 산출물은 업무지침이다. 제품 요구사항 P01~P12를 후속 설계와 검증의 기준으로 사용한다. |
| 가정 | 초기 구조는 Flutter 공통 앱과 네이티브 알림 어댑터다. 첫 버전은 기기 내 저장과 로그인 없는 사용을 제안한다. |
| 미결 | Flutter·Dart 버전, 라이브러리, 저장 엔진, 최소 OS와 OS별 예약 방식은 후보 검증 후 선택한다. |
| 검증됨 | 구현·자동 테스트·실기기 동작에 대해 S0에서 확보한 증거는 없다. 후속 단계에서 기기·OS·빌드와 결과를 기재한다. |

리드는 계약 변경 시 영향을 받는 데이터, 호출자, 기존 기기의 업그레이드 경로를 파악한다.
담당자 간 의미가 달라지는 변경은 메인에게 선택지와 사용자 영향을 전달해 공통안을 확정한다.

## Flutter 초기 구조와 소유권 제안

아래 경로는 후속 개발의 소유권 제안이다. S1에서 메인이 실제 경로와 공동 수정 절차를 등록한다.

| 영역과 제안 경로 | 담당 | 입력과 출력 |
|---|---|---|
| 조립 계층 `lib/app/` | 아키텍처 | 시작·복구 순서, 의존성 연결, 로캘 선택을 구성한다. |
| UI `lib/ui/` | UX·보상 | 읽기 모델을 그리며 사용자 의도를 명령으로 전달한다. 휴대폰과 태블릿의 배치를 결정한다. |
| 도메인 `lib/domain/` | 도메인·데이터 | 목표, 기록, 보상과 일정 규칙을 순수 연산으로 정의하고 저장·예약 인터페이스를 소유한다. |
| 데이터 `lib/data/` | 도메인·데이터 | 저장 인터페이스, 원자적 쓰기, 스키마 이행과 조회를 구현한다. |
| 플랫폼 `lib/platform/`, `ios/`, `android/` | 네이티브 알림 | OS 권한·예약·취소·응답을 공통 타입으로 변환한다. 서명·빌드 설정은 메인과 조율한다. |
| 지역화 `lib/l10n/` | 현지화 | 언어 리소스와 대체 언어 규칙, 표시 포맷과 번역 인수 검사를 관리한다. |
| 공통 설정·배포 파일 | 메인 | 담당자 제안과 호환성 근거를 받아 의존성과 빌드 설정을 통합한다. |

UI와 알림 응답은 동일한 도메인 명령을 호출한다. 도메인은 위젯·OS·저장 엔진·번역 문구에 의존하지 않는다.
조립 계층이 시계, 시간대, 저장소, 알림 어댑터를 주입한다. 테스트에서는 각각을 대체할 수 있게 한다.
알림 응답은 화면이 열리지 않은 상태에도 도착하므로 화면 초기화와 독립된 저장 진입점을 설계한다.

## 핵심 계약 초안

### 섭취와 하루 집계

- 프로필·설정, 날짜별 목표, 섭취 사건, 알림 회차, 날짜별 스티커 배치를 구분한다.
- 공통량은 mL로 전달한다. 50% 결과가 소수일 때의 정밀도·반올림은 S1에서 결정해 화면과 실제 저장에 같이 쓴다.
- 섭취 사건은 식별자, 양, 발생 시각, 당시 시간대, 적용 날짜와 입력 출처를 가진다. 알림 입력은 회차 식별자를 포함한다.
- 도메인 담당은 수동 입력·수정·삭제·복구와 날짜별 목표 변경의 명령·결과 예시를 제공한다.
- 날짜가 바뀌어도 이전 목표와 집계의 근거를 보존한다. 여행·서머타임과 과거 기록 수정 시 귀속 정책을 명시한다.
- 보상 구간은 표시용 백분율을 반올림하기 전 판정한다. 50·80·100% 경계와 각 경계 직전 값을 예시로 남긴다.
- UX는 날짜별 읽기 모델의 섭취량·목표·남은 양·달성률·스티커 등급과 배치 좌표를 사용한다.
- 저장소 이행은 스키마 버전을 기준으로 재시작할 수 있어야 한다. QA에는 이전 스키마 표본과 기대 집계를 넘긴다.

### 알림과 섭취 기록

- 도메인은 자동·수동 계획에서 개별 회차의 식별자, 예정 현지 시간·시간대, 예정량과 계획 버전을 생성한다.
- 네이티브 담당은 예약·취소 결과와 권한 상태를 반환하고 예약 실패·한도 도달 시 다시 맞출 수 있는 상태를 전달한다.
- 빠른 기록의 100%·50%는 회차 예정량 기준이다. 액션 값은 언어에 독립적인 식별자로 전달한다.
- 회차의 섭취 확정과 기록 삽입을 한 트랜잭션으로 처리한다. 두 액션이 경합해도 이미 확정된 회차는 기존 결과를 반환한다.
- 미루기·건너뛰기는 별도 상태 전이다. 미룬 시각, 기존 회차 처리, 오래된 응답의 처리 기준을 네이티브·도메인 담당이 합의한다.
- 목표 달성 시 도메인이 남은 당일 회차를 취소 대상으로 산출한다. 취소 실패는 복구 시 OS 예약 목록과 대조한다.
- 앱 접근이 가능한 상황에서는 권한 거부와 예약 실패의 영향을 설명하고 앱 안에서 직접 기록할 수 있게 한다.

### 언어와 지역

- 첫 언어팩 후보는 en, zh-Hans, zh-Hant, ja, ko, hi다. 인도 첫 언어를 힌디어로 가정하고 영어도 제공하는 안이다.
- 언어팩 등록 목록으로 확장하며 국가 코드에서 언어 하나를 강제하지 않는다. 중국어는 문자체를 구분한다.
- 설정은 시스템 언어 사용과 명시적 언어 선택을 저장한다. 언어, 표시 단위, 지역 형식, 시간대는 별도로 해석한다.
- UI·알림·스티커·접근성 텍스트는 메시지 키와 타입이 있는 인수를 사용한다. 번역자가 수치와 단위를 자연스럽게 배치할 수 있게 한다.
- 언어 변경 시 향후 예약의 표시 문구를 갱신하되 회차 식별자와 기록 이력을 유지한다. 이미 전달된 알림의 표시는 OS별로 확인한다.
- 현지화 담당은 오프라인 언어 전환, 대체 언어 순서와 날짜·숫자·단위 예시를 UI·네이티브·QA에 전달한다.

## 실기기 판정과 빌드 의존성

| 시험 조건 | 구분하여 기록할 결과 |
|---|---|
| 전경·백그라운드·일반 종료 | 화면이 떠 있는지, 프로세스가 살아 있는지, 예약 알림 표시와 빠른 기록 반영이 각각 가능한지 |
| iOS 앱 전환기 강제 종료 | 사용자가 앱을 쓸어 종료한 후의 표시·액션·재실행 후 기록 상태 |
| Android 최근 앱 제거 | 최근 앱 제거 후 프로세스와 알림 상태, 제조사 전원 관리 설정 |
| Android 설정의 강제 중지 | 명시적 강제 중지 후와 사용자가 다시 실행한 후의 예약 복구·기록 상태 |
| 권한 거부·집중 모드·절전·재부팅 | 알림 지연·숨김·차단을 구분하고 가능한 복구 시점과 제한을 기록 |

네이티브 담당은 실제 iPhone·iPad·Android 휴대폰·Galaxy Tab에서 기종·OS·설정·시각·빌드 식별자를 기록한다.
QA는 알림 노출, 액션 전달, 로컬 저장, 재실행 후 반영을 따로 판정한다. 시뮬레이터 결과는 실기기 결과와 구분한다.
iOS/iPadOS 빌드에는 호환되는 macOS와 Xcode가 필요하다. 실기기 설치 및 시험·출시 배포에는 해당 경로에 맞는 서명이 필요하다.
장비나 서명이 없으면 차단된 시험과 필요한 자원을 메인에 보고하고 Android·도메인·문서 검토를 진행한다.

## 단계별 할 일과 완료 기준

| 단계 | 아키텍처 리드 산출물 | 인수·검증 기준 |
|---|---|---|
| S0 팀·문서 (현재) | 경계, 계약 초안, 의존성과 소유권 제안 | 메인이 제품 요구와 역할별 지침 간 충돌을 검토한다. |
| S1 개발기반·계약 | 개발환경 후보, 명령·결과 예시, 스키마·이행안, 초기 빌드 경로 | 도메인·네이티브·UX·현지화·QA가 동일한 회차 및 하루 예시로 입출력을 설명한다. |
| S2 알림 시제품 검증 | OS 상태별 결과표와 패키지·최소 OS 선택 근거 | 실기기에서 빠른 기록·재전달·복구를 관찰하고 기기별 제약과 대체 동작을 기록한다. |
| S3 전체기능·지역화 구현 | 목표 설정부터 스티커 달력까지 통합한 빌드와 여섯 언어팩 | 날짜 경계·재시작·언어 변경 후 예약과 기록이 합의한 계약을 만족한다. |
| S4 통합·실기기 QA | 네 기기군의 시험 증거와 결함 처리 기록 | QA가 주요 흐름과 실패·복구 경로를 재현하고 남은 결함의 출시 영향을 판정한다. |
| S5 시험배포 | 시험 서명 빌드, 설치·업그레이드 및 데이터 유지 결과 | 시험 채널에서 받은 빌드로 설치 후 실행하고 업그레이드 전후의 기록을 대조한다. |
| S6 스토어 자료·출시 빌드 | 버전·서명·권한·개인정보 선언과 빌드 대응표 | QA·출시 담당이 스토어 설명과 실제 권한·저장·알림 동작의 일치를 확인한다. |
| S7 심사·공개 | 심사 질의에 답할 기술 근거와 공개 빌드 식별자 | 메인이 배포 범위를 확인하고 양 스토어 공개본의 설치·실행 결과를 기록한다. |
| S8 운영 | OS 변경, 이행 실패, 알림 누락의 재현·수정 계획 | 지원 버전별로 수정과 이전 기록 보존을 재검증하고 대응 이력을 남긴다. |

## 인수인계와 남은 결정

- S1에서 도메인 담당과 회차 상태 전이, 하루 귀속, 반올림, 목표 변경과 이전 날짜 재집계 정책을 정한다.
- S1에서 UX·보상 담당과 직접 기록·오입력 복구 및 스티커 배치 모델을 맞추고 화면 크기 변경 예시를 교환한다.
- S1에서 현지화 담당과 기기 언어 불일치 시 대체 순서, 지역별 단위 기본값과 시스템 언어 변경 시 반영 시점을 정한다.
- S2에서 네이티브 담당과 예약 개수 제한, 재예약 시점, 백그라운드 저장 지원 및 제한 시 대체 흐름을 확정한다.
- QA·출시 담당에게 상태표, 재전달·날짜 경계 표본, 테스트 장비·서명 의존성을 전달한다. 검증 누락에는 후속 담당과 단계를 붙인다.
- 권장 목표 산정 근거와 적용 연령, 대상 국가, 기기 내 저장·로그인 없는 구성의 확정 여부는 메인이 관리한다.
- 메인에게 변경 파일, 결정·가정, 실제 검증과 남은 의존성을 전달한다. 단계 완료는 해당 단계의 증거 확보 후 기록한다.
