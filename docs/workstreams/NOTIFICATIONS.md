# 네이티브 알림 업무지침

Astra 알림 리드는 아이폰·아이패드·안드로이드 휴대폰·갤럭시탭의 로컬 알림을 담당한다.
S0의 산출물은 이 계획서다. 아래 계약과 기대 결과는 S1 이후 합의·검증할 제안이다.

## 담당 범위와 협업

- 도메인 담당은 도메인 계층에서 자동·수동 시간 배치 규칙과 회차별 예정량 계산을 소유한다.
- 알림 리드는 규칙에 필요한 입력과 플랫폼 요구사항을 전달하고 OS 예약·취소, 버튼 콜백 수신·재시도와 장애 복구를 소유한다.
- 도메인 담당이 섭취 원장과 날짜별 집계를 소유한다. 알림 리드는 원장에 적용할 명령을 전달한다.
- UX 담당과 권한 안내, 놓친 알림, 앱에서 기록하는 대체 경로를 설계한다.
- 현지화 담당은 문구와 단위 표현을, 알림 리드는 OS에 전달되는 최종 제목·본문·버튼을 검토한다.
- 첫 버전은 기기 내 저장을 전제로 하며 오프라인 상태의 예약과 탭 처리도 검증한다.

## 시간 배치와 회차별 예정량

- 자동 모드는 기상부터 취침까지 조용한 시간을 제외한 구간에 회차를 분산한다.
- 목표에서 이미 기록한 양을 빼고 회당 용량으로 나눈다. 마지막 회차에는 양수인 잔여량만 배정한다.
- 직접 모드는 사용자가 지정한 시각을 사용한다. 중복 시각이나 조용한 시간과의 충돌은 저장 전에 표시한다.
- 자정을 넘는 활동 구간은 도메인의 하루 경계에 따라 각 날짜의 목표와 연결한다.
- 남은 시간에 회차를 모두 배치할 수 없으면 무리하게 간격을 줄이거나 한 회차에 몰아넣지 않는다.
- 미루기는 같은 회차의 다음 유효 시각으로 이동한다. 건너뛰기는 그 회차를 종료하고 섭취량을 더하지 않는다.
- 유효한 시간이 남지 않은 미루기 요청은 만료 처리하고 다음 날 목표로 넘기지 않는 방안을 검토한다.
- 목표 달성 시 해당 날짜의 모든 남은 예약과 표시 중인 알림을 가능한 범위에서 회수한다.
- 기록 수정·삭제로 목표 아래로 돌아오면 미래 유효 구간만 다시 계획한다. 지난 회차를 재생하지 않는다.

## 데이터 계약 초안

| 항목 | 의미와 처리 원칙 |
|---|---|
| occurrenceId | 기기 내 영속 회차 ID. 앱 재시작·미루기·언어 변경 시 같은 회차에 유지한다. |
| revision | 예약본의 세대. 시각·용량·문구 변경으로 재발행할 때 올려 오래된 버튼을 식별한다. |
| dayKey, zoneId | 발행 시 도메인의 귀속 날짜와 시간대. 콜백 수신 날짜만으로 다시 정하지 않는다. |
| localTime, scheduledAt | 사용자가 보는 현지 시각과 해당 예약의 절대 시각을 함께 보관한다. |
| plannedMl, fullMl, halfMl | 발행 시 고정한 예정량과 두 버튼의 실제 기록량. 정수 mL 규칙을 도메인과 합의한다. |
| action, receivedAt | 전체·절반·미루기·건너뛰기 동작과 기기 수신 시각. 표시 문자열과 독립적으로 해석한다. |
| intakeId, sourceOccurrenceId | 원장 기록과 회차 연결. 회차를 소비하는 기록에 고유 제약을 둔다. |
| platformRequestId | OS 예약 식별자와 회차·세대 대응표. 취소·재조정과 장애 복구에 사용한다. |

- 두 버튼 모두 비율과 실제 양을 표시한다. 예정량 150 mL의 예는 ‘100% · 150 mL’, ‘50% · 75 mL’다.
- 홀수 용량과 1 mL의 절반 처리 방식을 S1에서 결정하고 화면·알림·원장이 같은 변환 결과를 사용한다.
- 원장을 바꾸기 전에 회차와 세대, 만료 여부, 목표 상태를 기기 내 저장소에서 확인한다.
- 같은 회차에 전체·절반을 연달아 눌러도 최초 유효 동작 한 건만 기록하도록 원자적으로 처리한다.
- 미루기와 세대 증가도 한 트랜잭션으로 처리한다. 이전 세대로 재전달된 미루기가 예약을 늘리지 않게 한다.
- 기록 삭제 뒤에도 소비한 회차의 상태를 보존해 오래된 콜백으로 기록이 부활하지 않게 한다.
- 앱에서 해당 알림을 열어 직접 입력하면 같은 회차 ID를 사용한다. 독립적인 직접 입력에는 별도 기록 ID를 쓴다.
- 같은 시각·같은 양만으로 독립 입력을 합치지 않는다. 동시 저장은 원장에서 직렬화하고 목표를 다시 평가한다.
- 지난 날짜, 교체된 세대, 취소된 회차의 탭은 자동 집계하지 않는다. 필요하면 앱에서 날짜와 양을 확인해 직접 기록한다.
- 같은 날 늦게 도착한 유효 회차의 허용 기한과 귀속 시각은 S1에서 도메인과 합의한다.

## 예약 한도와 변경 복구

- OS별 대기 예약 한도와 계수 단위를 공식 문서에서 조사하고 실기기로 대조한다.
- 가까운 미래부터 유한한 구간만 예약하며, 미루기용 여유분과 구간 길이는 확인한 한도에 맞춘다.
- 앱 시작·복귀, 유효한 알림 동작, 설정 저장 시 희망 예약과 실제 대기 목록을 비교해 빈 구간을 채운다.
- OS가 목록 조회를 제한하면 저장한 대응표를 기준으로 재조정하고 불확실한 상태를 시험 결과에 남긴다.
- 원장 갱신과 OS 예약 사이에서 프로세스가 끝날 수 있다. 희망 상태를 먼저 저장하고 다음 기회에 차이를 복구한다.
- 앱이 장기간 열리지 않고 OS 실행 기회도 없으면 예약 구간 이후 공지가 끊길 수 있다. 무기한 전달을 약속하지 않는다.
- 표시 언어가 바뀌면 미처리 예약의 제목·본문·버튼을 새 언어로 갱신하고 이전 세대 콜백을 걸러낸다.
- 목표·회당 용량·활동 시간 수정 시 이미 소비한 회차를 보존하고 남은 예약만 다시 계산한다.
- 시간대 변경 시 현지 반복 시각에서 절대 시각을 다시 구한다. 완료 기록의 날짜 귀속은 도메인 정책을 따른다.
- DST로 사라지는 시각은 다음 유효 시각, 두 번 나타나는 시각은 최초 한 번이라는 후보 정책을 검증한다.
- 이동 결과가 조용한 시간과 겹치거나 회차가 중복될 때에도 한 회차를 두 번 발행하지 않는다.

## 실기기 상태별 검증표

모든 행은 네 기기 유형에서 확인할 항목이다. 기기·OS·앱 빌드별 관찰 전에는 지원 여부를 확정하지 않는다.

| 상태 | 시험과 관찰 지점 |
|---|---|
| 앱 열림 | 전경 표시와 앱 내 안내 중복 여부, 두 버튼의 용량·원장 기록을 확인한다. |
| 백그라운드 | 잠금·잠금 해제 상태에서 버튼 접근, 탭 후 처리 시점과 저장 지속성을 확인한다. |
| 프로세스 없음 | OS에 의해 프로세스가 사라진 뒤 이미 예약한 알림과 콜드 스타트 콜백을 확인한다. |
| 사용자 강제종료 | iOS 앱 전환기 종료, Android 최근 목록 제거와 설정의 강제 중지를 구분해 결과를 기록한다. |
| 재부팅 | 재부팅 후 최초 잠금 해제 전후 및 앱 재실행 전후에 예약 잔존·중복·복구를 확인한다. |
| 권한 변경 | 최초 요청, 거부, 설정에서 철회·복구, Android 채널별 차단을 구분해 앱 상태 표시를 본다. |
| 집중·방해 금지 | 표시·소리·요약에 의한 지연과 앱의 기록 처리 성공을 별도로 관찰한다. |
| 절전 제한 | Android 절전 모드·제조사 배터리 설정에서 전달 지연과 백그라운드 복구 기회를 관찰한다. |

- 공식 Apple UserNotifications 문서에서 동작 카테고리·백그라운드 응답·권한 상태·예약 취소 절차를 확인한다.
- Android Developers 문서에서 알림 런타임 권한·채널·알람 정밀도·절전·재부팅·강제 중지 동작을 확인한다.
- 정확한 시각 예약의 필요성과 권한 요청 시점은 대안의 전달 지연을 측정한 후 검토한다.
- 라이브러리·최소 OS 버전·권한 정책은 공식 문서의 적용 버전과 S2 시제품 결과를 비교해 결정한다.
- 축약·확장 알림, 잠금 화면, 태블릿과 큰 글꼴에서 버튼 노출과 스크린리더 읽기 순서를 기록한다.
- OS가 빠른 동작을 숨기는 조건에서는 알림 탭으로 해당 회차를 앱에서 열고 실제 양을 확인하게 한다.

## 단계별 산출물과 인수인계

| 단계 | 알림 담당 산출물과 다음 단계 조건 |
|---|---|
| S0 팀·문서 | 책임, 계약 후보, 미확정 정책과 기기 시험 항목을 문서화한다. |
| S1 개발기반·계약 | 날짜·용량·수명주기·재시도 계약을 아키텍처 및 도메인 담당과 합의한다. |
| S2 알림 시제품 | 양 플랫폼에서 예약→수신→버튼→저장 경로를 시연하고 공식 문서와 판단 근거를 남긴다. |
| S3 전체기능·지역화 | 자동·직접·미루기·건너뛰기·목표 취소와 여섯 언어팩의 예약 갱신을 연결한다. |
| S4 통합·실기기 QA | 네 기기에서 상태표를 실행하고 결함 재현 조건·대체 흐름·잔여 위험을 넘긴다. |
| S5 시험배포 | 시험 빌드에서 신규 설치·업데이트·장시간 미실행 후 예약 및 콜백 복구를 확인한다. |
| S6 출시 빌드·스토어자료 | 릴리스 구성에서 사용 권한과 안내 문구, 실제 지원 기능과 스토어 설명을 대조한다. |
| S7 심사·공개 | 알림 권한·버튼 접근·기록 확인의 심사 경로를 제공하고 공개 빌드에서 재확인한다. |
| S8 운영 | OS 업데이트별 회귀 시험과 예약 중단 문의 재현을 맡고 호환성 표를 갱신한다. |

## 시험 자료와 파일 소유권

- 예약 계산 시험에는 잔여량, 자정, DST 전환, 수동 시각 중복, 조용한 시간과 미루기의 충돌을 포함한다.
- 원장 시험에는 동시 버튼, 재전달, 수동 입력과의 경합, 목표 달성 직후 탭, 쓰기 직후 강제 종료를 포함한다.
- 지역화 표본은 en, zh-Hans, zh-Hant, ja, ko, hi 전부에서 버튼과 본문에 실제 용량이 일치하는지 확인한다.
- 시험 기록에는 기기·OS·앱 버전, 권한·집중 설정, 예약 시각과 표시·탭·저장 시각, 기대값과 관찰값을 남긴다.
- 출시 담당에게 지원 조합, 알려진 제약, 재현 절차, 설정 복구 경로와 미검증 조합을 구분해 전달한다.
- 향후 Flutter 알림 어댑터·플랫폼별 예약/동작 수신부·해당 시험의 파일 소유자는 알림 리드로 제안한다.
- 구체적인 경로는 S1에서 메인이 배정한다. 공용 의존성·빌드 설정과 원장 스키마 변경은 해당 소유자와 조정한다.
- S2에는 양 플랫폼 개발 환경과 실기기 접근, S4에는 네 기기 유형과 지원 후보 OS 조합이 필요하다.
