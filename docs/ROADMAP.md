# 코드 작성부터 글로벌 출시까지

S0 팀 구성과 업무지침 작성·검토를 완료했다. 사용자가 선택한 `jchjch11-png/code`로 Git 저장소를 준비했으며, S1의 앱 기반 구축과 S2~S8은 후속 실행 계획이다.

## 의존성과 병렬 작업

```text
S0 팀·업무지침
  ↓
S1 앱 기반 + 데이터·알림·지역화 공통 계약
  ↓
S2 알림 시제품 검증 ── 핵심 플랫폼 제약 확인
  ↓
S3 도메인·저장 ─┬─ UX·스티커 ─┬─ 언어팩·형식
               └──── 통합 ────┘
  ↓
S4 실기기 QA → S5 시험 배포 → S6 출시 자료 → S7 심사·공개
                                                     ↓
                                                   S8 운영
```

- S1~S2 동안 UX 설계·문구 구조·테스트 계획은 병렬 준비할 수 있다.
- 알림 시제품의 핵심 제약을 확인하기 전에는 전체 기능을 출시 가능한 것으로 가정하지 않는다.
- S3에서는 계약을 기준으로 담당 파일을 나눈다. 완료 순서가 달라도 통합 기준은 동일하다.
- 현지화는 S1부터 구조에 포함한다. 전체 개발이 끝난 뒤 일괄 번역하는 작업으로 미루지 않는다.
- 출시용 언어 검수는 S3부터 준비하고 S6 전에 완료한다. AI 번역 초안과 언어 검수 완료 상태를 구분한다.

## 처음 고정할 공통 계약

S1 종료 전 아키텍처·도메인·알림·현지화 담당이 아래 항목을 메인에 인계한다.

1. 섭취량의 저장 단위, 변환·반올림, 전체/절반 버튼의 실제 기록량.
2. 알림 회차 ID, 예약 세대, 이벤트 중복 키, 기록 취소·수정의 처리.
3. 하루 ID와 목표 스냅샷, 자정·시간대 이동·과거 알림의 귀속 규칙.
4. 기록·목표 변경 시 보상 재계산과 남은 알림 취소·재평가.
5. 언어 ID, 시스템 언어 해석, 영어 fallback, 네이티브 알림 문구 갱신.
6. 스티커 자산 ID와 날짜 칸 배치 정보, 기록 변경 시 보상 일치.

S0 교차검토에서 미루기·언어 변경은 동일 회차 ID를 유지하며 예약 세대를 올리는 초안으로 통합했다. 전체/절반 섭취 확정은 회차의 전체 수명에서 최대 한 번이다. 도메인과 알림 담당은 S1에서 이 초안을 상태 전이표와 예제로 구체화한다.

자동 시간 배치의 순수 규칙·예정량 계산은 도메인 계층, OS 예약·버튼 콜백·예약 복구는 네이티브 계층이 소유한다. 언어 담당은 표시용 포맷을 맡고 입력값의 기준 단위 정규화는 도메인 계약을 따른다.

나머지 정책 제안이 서로 다르면 메인이 S1 계약으로 통합한다. 아직 미확정인 값을 구현 완료된 사실로 문서화하지 않는다.
